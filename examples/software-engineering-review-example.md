# Example：软件工程代码审查适配

> 本示例展示如何将 `agentic-method` 的核心协议适配到 C/C++ 系统编程项目的代码审查任务。
> 
> 使用时，请替换 `{PROJECT_NAME}`、`{LANGUAGE}`、`{BACKEND_A}` 等占位符。

---

## 0. 任务定义 (CTX)

```markdown
(CTX) 审查目标：{PROJECT_NAME} 的 {LANGUAGE} 代码库、模块、PR 或特定改动
(CTX) 审查范围：文件清单 / commit 范围 / PR 链接
(CTX) 审查目标：识别正确性、性能、可维护性、安全/稳定性、测试/可验证性五类风险
```

---

## 1. 审查流程

```
范围冻结 (CTX) → 信息收集 (R) → 假设生成 (T) → 验证实验 (E) → 观察更新 (OU) → 审查报告 (M)
```

---

## 2. 主题分组检查清单

### 2.1 内存安全与生命周期

- [ ] 是否存在 use-after-free / double-free / memory leak？
- [ ] 智能指针/RAII 使用是否正确？
- [ ] 是否存在越界访问？
- [ ] 临时对象生命周期是否安全？

### 2.2 并发与同步

- [ ] 异步操作是否有显式同步点？
- [ ] 锁的粒度是否合理？
- [ ] 是否存在死锁或数据竞争？
- [ ] 线程局部存储使用是否正确？

### 2.3 ABI/链接/API 设计

- [ ] 公共头文件布局是否稳定？
- [ ] 是否存在符号冲突或 ODR 违规？
- [ ] 接口变更是否破坏向后兼容？

### 2.4 测试覆盖与语义回归

- [ ] 修改是否伴随单元测试？
- [ ] 是否覆盖了 copy/move/lifetime 语义？
- [ ] 是否覆盖了异步路径？

### 2.5 性能与后端调度

- [ ] 是否存在冗余同步或内存拷贝？
- [ ] 后端调度优先级是否合理？
- [ ] 编译优化选项（如 LTO）是否正确配置？

---

## 3. 验证手段

1. **静态验证**：代码走查、编译器警告、静态分析工具。
2. **动态验证**：单元测试、集成测试、压力测试。
3. **交叉验证**：不同后端 ({BACKEND_A} vs {BACKEND_B}) 对照、与历史 MEM 对比。

---

## 4. 输出格式

```markdown
# Code Review Report

## 摘要
- 审查范围：
- 关键发现数：
- 建议行动数：

## 关键发现（按 P0/P1/P2 排序）

### P0-X: <标题>
- 描述：
- 证据等级：(F0-F4)
- 置信度：(CONF: ...)
- 验证轨迹：(PREDICTION) → (OBSERVATION) → (VERDICT)
- 建议：

## 假设验证轨迹
## 专题分析
## 推荐行动清单
```

---

## 5. HITL 触发条件

- 公共接口变更
- 绕过测试
- 安全漏洞
- 与工程约束冲突
- 大规模重构
