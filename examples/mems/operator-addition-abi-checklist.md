# 新增公共枚举/接口时必须执行的 ABI 与语义检查清单

**发现日期**：2026-07-29  
**来源任务**：全局代码审查后发现算子枚举变更未同步引发调度表维度问题

## Rule

在项目中新增公共枚举值（如算子类型、设备类型、数据类型）或修改公共接口时，必须完成一份固定检查清单，禁止只改 enum 不更新依赖该 enum 的调度表、static_assert 与 kernel 注册。

## When

- 向算子枚举添加新算子（如激活函数、归一化层等）
- 向设备类型枚举添加新后端
- 向数据类型枚举添加新类型
- 修改上述枚举的顺序或在已有值之间插入新值

## Because

1. 调度器内部可能使用 `std::array<std::array<...>, OP_COUNT>` 作为 kernel 查找表，`OP_COUNT` 直接来自枚举的计数项。只改 enum 不改 static_assert 或注册表会导致数组维度与注册逻辑错位。
2. enum 值顺序改变会破坏已编译二进制中保存的枚举值语义，属于 ABI 破坏。
3. 新增数据类型会触发类型检查、kernel dtype 分发、后端 shader 类型声明等多处联动。
4. 缺少清单时，人类容易遗漏“不重要但关键”的同步点（如 static_assert 中的硬编码数字）。

## Checklist

新增算子时必须逐项确认：

- [ ] 新枚举值追加到计数项之前，禁止在已有值之间插入。
- [ ] 同步更新调度器头文件中的 static_assert（例如 `OP_COUNT == 28`）。
- [ ] 在调度器初始化函数中为新算子注册所有目标后端的 kernel；不支持的设备必须显式返回 `nullptr` 或抛出明确错误，禁止留下未声明的空槽。
- [ ] 若涉及自动微分，在节点注册表中注册对应的反向节点类型（或确认该算子不需要反向）。
- [ ] 在 kernel 头文件中声明新 kernel；已声明的 kernel 必须有对应实现。
- [ ] 更新 ABI 策略文档中的“已知 ABI 破坏记录”。
- [ ] 补充单元测试，覆盖数值正确性、跨设备一致性和反向梯度（如适用）。

新增设备类型时必须逐项确认：

- [ ] 同步更新调度器头文件中的设备计数 static_assert。
- [ ] 在设备可用性检查函数中声明该设备是否可用。
- [ ] 在分配器管理器中注册对应分配器。
- [ ] 为所有已有算子决定该设备的 kernel 策略：实现、降级到通用后端，或标记为不支持。

新增数据类型时必须逐项确认：

- [ ] 在类型检查函数中增加类型匹配分支。
- [ ] 在元素大小工具函数中增加新类型的大小。
- [ ] 评估所有后端 kernel 是否需要新增 dtype 分支（GPU shader、CPU/SIMD/专用指令集）。

## Verification

- 编译必须失败于 static_assert，直到维护者显式更新硬编码数字。
- 运行 ABI 审计脚本应在公共头文件变化时给出提示。
- 新增算子后，对应单元测试应全部通过。

## Failure cases

- 只改算子枚举头文件，未改调度器的 static_assert，导致编译通过但调度表错位。
- 在 enum 中间插入新值，导致已保存模型/序列化数据中的枚举值错误映射。
- 声明了 kernel 但未实现，链接时或运行时出现未定义符号/空指针崩溃。
- 新增数据类型后未更新类型检查，导致该类型张量被错误拒绝。
