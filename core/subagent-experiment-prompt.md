# SUBAGENT EXPERIMENT PROMPT：为子 Agent 设计实验协议

> 适用：当任务过大或需要并行探索时，将工作拆分为多个子 Agent，每个子 Agent 执行受控实验，并汇总结果。

---

## 1. 阶段一：任务分解与上下文封装 (R)

### 1.1 (CTX) 复述模板

```markdown
(CTX) 父任务：<一句话>
(CTX) 可拆分子任务：<列表>
(CTX) 子 Agent 数量：<N>
(CTX) 共享上下文：<所有子 Agent 必须已知的信息>
(CTX) 合并标准：<何时/如何汇总结果>
(CTX) 全局约束：<硬约束>
```

### 1.2 子任务拆分原则

1. **MECE**：子任务之间互斥且完全穷尽搜索空间。
2. **单一变量**：每个子 Agent 原则上只改变一个变量或验证一个假设。
3. **可独立运行**：每个子 Agent 拥有独立的输入、环境、输出路径。
4. **信息收益最大化**：优先拆分能排除最大搜索空间的实验。

## 2. 阶段二：实验矩阵设计 (T)

### 2.1 实验矩阵模板

```markdown
| 子 Agent ID | 任务 | 假设 | 变量 | 对照组 | 实验组 | 输出文件 | 成功标准 | 预期置信度 |
|---|---|---|---|---|---|---|---|---|
| A1 | ... | ... | ... | ... | ... | ... | ... | medium |
| A2 | ... | ... | ... | ... | ... | ... | ... | high |
```

### 2.2 子 Agent Prompt 模板

为每个子 Agent 生成独立 prompt，必须包含：

```markdown
# 子 Agent 任务：<子任务名>

## 父任务上下文
<简洁说明父任务与全局约束>

## 你的专属任务
<具体、可验证>

## 实验设计 (EXP)
<假设、方法、判断标准>

## 禁止事项
<不得修改的代码、不得跨越的边界>

## 输出要求
<必须生成的文件、报告格式、返回给父 Agent 的摘要>

## Prompt 注入说明
- 该子 Agent 仅接收本 prompt，禁止注入完整 8 篇 prompts。
- 父任务上下文控制在 3 句话以内。

## (HITL) 触发条件
<遇到什么情况必须停止并请求人类确认>
```

### 2.3 反事实与消融设计

```markdown
(CFC) 子 Agent A1 若改变另一个变量，结果是否 still hold？
(ABL) 子 Agent A2 若移除某组件，是否能复现问题？
(CTRL) 子 Agent A3 是否运行了未改动的基线？
```

---

## 3. 阶段三：子 Agent 执行与监控 (E)

### 3.1 执行协议

1. **并行启动**：独立子 Agent 同时运行。
2. **沙箱隔离**：每个子 Agent 在独立工作目录或 git 分支上工作。
3. **定期检查点**：每完成一个 (R/T/E/M) 循环，子 Agent 必须向父 Agent 汇报状态。
4. **失败处理**：若子 Agent 失败，记录失败原因，不直接放弃整个任务。

### 3.2 父 Agent 汇总

收到所有子 Agent 结果后，必须：

```markdown
## 汇总表
| 子 Agent | 结果 | 支持 / 推翻假设 | 关键数据 | 置信度 |
|---|---|---|---|---|
| A1 | PASS | 支持 H1 | ... | high (F0×3) |
| A2 | FAIL | 推翻 H2 | ... | high (F0×2) |

## 交叉验证与分支处理
(BRANCH) 解释 1：若 A1 与 A2 一致，则合并到统一结论。
(BRANCH) 解释 2：若 A1 与 A2 矛盾，则可能是假设空间划分不完整或存在隐藏变量。
(MERGE) 综合结论：
- 最可能根因 / 最佳方案：
- 置信度：(CONF: <level>, <证据统计>)
- 剩余不确定性：
- 下一步实验：
```

## 4. 阶段四：报告与沉淀 (M)

### 4.1 实验 orchestration 报告

写入 `{MEMORY_DIR}/reports/YYYY-MM-DD/exp-<YYYYMMDD>-<title>.md`：

```markdown
# 子 Agent 实验报告：<标题>

## 1. 父任务与分解理由
## 2. 实验矩阵
## 3. 各子 Agent 结果
## 4. 交叉验证与矛盾分析
## 5. 综合结论
## 6. 对抗思考 (ADV)
## 7. 可复现脚本与命令
## 8. 状态：CONCLUDED / NEEDS_MORE_EXP
```

### 4.2 对抗思考 (ADV)

```markdown
(ADV) 子任务拆分是否遗漏了关键变量？
(ADV) 子 Agent 之间是否存在隐式耦合？
(ADV) 是否存在更高效的信息收益拆分方式？
(ADV) 失败子 Agent 的结果是否被正确利用？
```

---

## 5. (HITL) 决策门

1. 子 Agent 涉及代码提交或修改公共代码前必须确认。
2. 子 Agent 实验结果互相矛盾时必须请求人类裁决。
3. 子 Agent 发现的根因需要架构级改动时必须确认。
4. 父 Agent 综合结论置信度为 low 时必须确认。

### 5.1 HITL_REJECTED 记录

若人类否决了子 Agent 拆分方式、实验设计、综合结论或知识沉淀，必须立即记录 `(HITL_REJECTED)`：

```markdown
(HITL_REJECTED) [YYYY-MM-DD HH:MM:SS]
- 被否决方案: <Agent 原本提议>
- 人类理由: <逐条记录>
- Agent 隐藏假设: <未显式声明的假设>
- 表层优点: <为什么看起来合理>
- 深层缺陷: <为什么被否决>
- 替代方向: <人类建议>
- 假设更新: H<x>: <old> → <new>
- 应生成的 MEM: <标题>
```

- 写入当前 reasoning log。
- 若可迁移，额外生成 `{MEMORY_DIR}/memories/YYYY-MM-DD/hitl-rejected-<title>.md`。
- (M) 阶段输出：`(AUDIT) 已记录 HITL_REJECTED：<描述>`。
