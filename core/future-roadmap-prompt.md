## 2. 阶段二：目标树与依赖图 (T)

### 2.1 目标树

```markdown
(T) 终极目标 O
  ├── 子目标 O1
  │     ├── 前置条件 P1
  │     └── 前置条件 P2
  ├── 子目标 O2
  │     ├── 前置条件 P3
  │     └── 风险 R1
  └── 子目标 O3
```

每个节点必须标注：

- `(CONF: <level>, <证据统计>)`：目标可行性置信度
- `(HITL)`：是否需人类确认
- `(EXP)`：验证目标是否达成的最小实验

### 2.2 依赖图 (DEPENDENCY_GRAPH)

```markdown
(DEPENDENCY_GRAPH)
[O1] → [P1] → [P2]
[O2] → [P3]
[O1] → [O2]  (O2 是 O1 的下游依赖)
```

### 2.3 反事实分析 (CFC)

```markdown
(CFC) 若跳过 O1 直接做 O2，O 是否仍可能达成？
(CFC) 若资源减半，哪些子目标必须被砍掉？
(CFC) 若外部环境变化（如 {BACKEND_A} API 变更），哪些依赖会失效？
```

## 7. (HITL) 决策门

以下情况必须停止并请求人类确认：

1. 路线涉及架构级重构或公共接口变更。
2. 路线会改变默认行为或用户可见语义。
3. 路线依赖未验证的第三方技术或硬件特性。
4. 路线砍掉已有功能或降低现有测试覆盖。
5. 里程碑跨度超过 3 个月且无中间验收点。
6. 规划结论将固化为项目 OKR 或资源分配依据。

### 7.1 HITL_REJECTED 记录

若人类否决了路线、里程碑或优先级，必须按 master-prompt 要求记录完整 `(HITL_REJECTED)` 轨迹。
