## 1. 阶段一：推理目标与上下文 (R)

### 1.1 (CTX) 复述模板

```markdown
(CTX) 推理主题：<一句话>
(CTX) 已知事实：<列出已验证的命题>
(CTX) 未知 / 假设：<列出待验证的命题>
(CTX) 推理目标：<需要回答的问题或做出的决策>
(CTX) 约束：<逻辑 / 工程 / 资源约束>
```

### 1.2 证据分级

```markdown
| 等级 | 含义 | 可使用性 |
|---|---|---|
| F0 | 直接观察 / 已运行测试输出 | 可作为前提 |
| F1 | 代码阅读得到的直接语义 | 可作为前提 |
| F2 | 文档 / 注释声明 | 需交叉验证 |
| F3 | 间接推断 | 只能作为假设 |
| F4 | 模型先验 / 常见模式 | 不能直接作为前提，必须验证 |
```

禁止将 F3/F4 等级的事实当作 F0/F1 使用。

### 1.3 证据分级正反面示例

**Bad**（把 F4 当 F0）：
```markdown
(F0) {BACKEND_A} 的 CrossEntropy 梯度计算一定需要显式 flush，否则就会出错。
```

**Good**（明确等级）：
```markdown
(F0) 在当前 {DATASET_NAME} 测试（batch=128, 15 epoch）中，未加 flush 时 {BACKEND_A} 准确率 9.87%。
(F0) 添加 {BACKEND_A}_flush_wait(true) 后，{BACKEND_A} 准确率 99.31%。
(F1) CrossEntropyNode::backward 的当前实现未调用 {BACKEND_A}_flush_wait。
(F3) 其他 {BACKEND_A} Node 可能也存在类似缺失（待验证）。
(F4) 一般而言，GPU 异步计算读取前需要同步（仅作启发，非当前证据）。
```

**Bad**（证据等级与结论置信度不匹配）：
```markdown
(CONF: high) 根因已确定，因为 {BACKEND_A} 异步执行通常需要同步。
```

**Good**（证据等级与结论置信度匹配）：
```markdown
(CONF: high, F0×3, F1×2) 根因已确定：修复前/修复后/撤回修复均复现，且代码阅读确认缺少 flush。
```

## 2. 阶段二：结构化推理 (T)

### 2.1 逻辑树

```markdown
(T) 目标：证明 / 决策 X
  ├── 子问题 X1
  │     ├── 证据 E1 (F0)
  │     └── 证据 E2 (F1)
  ├── 子问题 X2
  │     ├── 假设 H1 (F3)
  │     └── 待验证：EXP-1
  └── 子问题 X3
        └── 反事实 (CFC)：若 Y 不成立，X 是否 still hold？
```

### 2.2 推理质量检查清单

每完成一步推理，必须自检：

```markdown
- [ ] 前提是否全部来自 F0/F1？
- [ ] 是否存在隐含假设未显式声明？
- [ ] 推理步骤是否可形式化？
- [ ] 是否存在确认偏误（只收集支持证据）？
- [ ] 是否考虑了反例？
- [ ] 结论是否过度泛化？
```

### 2.3 反事实推理 (CFC)

```markdown
(CFC) 若前提 P 不成立，结论 C 是否仍成立？
(CFC) 若只改变变量 V，现象是否改变？
(CFC) 是否存在其他共同原因导致 C？
(CFC) 结论 C 是否只是 A 与 B 的相关性，而非因果？
```

## 3. 阶段三：方法论应用 (E)

### 3.1 方法选择矩阵

| 问题类型 | 首选方法 | 关键动作 |
|---|---|---|
| 定位异常范围 | 二分法 | 每次排除一半搜索空间 |
| 验证组件贡献 | 消融实验 | 移除 / 替换单一组件 |
| 精确归因 | 反事实推理 | 单一变量变化 |
| 建立可信基线 | 对照实验 | CPU / 旧版本 / 参考实现 |
| 保证长期正确 | 单元测试 | fail before fix / pass after fix |
| 追踪错误传播 | 中间变量输出 | 量化差异、最小集合 |

### 3.2 复杂推理分解

当问题复杂时，必须：

1. 将大问题拆分为可独立验证的子问题。
2. 为每个子问题指定验证方法。
3. 使用子 Agent 并行探索（参考 subagent-experiment-prompt.md）。
4. 汇总结果时检查一致性与矛盾。

